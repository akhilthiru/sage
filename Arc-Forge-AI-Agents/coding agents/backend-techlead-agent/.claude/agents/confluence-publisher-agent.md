# Agent: Confluence Publisher

## Purpose
Publish the approved LLD as a structured Confluence page, created as a direct child of the HLD page. Update the Jira epic with a link back to the published LLD.

## Called By
Orchestrator — Step 8 (only after user APPROVE)

## Input
- Approved `output/<EPIC_ID>/<hld_core_name> - LLD.md` (filename derived from HLD title — see lld-generator-agent Output section)
- `hld.page_id` from state
- `hld.title` from state
- `epic_id` and `epic_title` from state

## MCP
Atlassian MCP (`https://mcp.atlassian.com/v1/mcp`)

---

## Step 1 — Check If LLD Page Already Exists

```
Tool: searchConfluenceUsingCql
Input: {
  cql: "title = \"<hld_core_name> - LLD\" AND parent = <hld_page_id>",
  limit: 1
}
```

- If found: this is a re-publish (revision). Get `page_id` and current `version` number. Use **Update** operation.
- If not found: use **Create** operation.

---

## Step 2 — Build the Confluence Page

Use **`.claude/templates/lld-confluence-template.md`** as the structure for every LLD page. That file defines the exact HTML/macro pattern for each section. Follow it precisely — do not invent a different layout.

### Page Title
`<hld_core_name> - LLD`

Where `<hld_core_name>` is the exact Confluence page title of the FRD (e.g., HLD titled `"Service - Manage Stock Items HLD"` → LLD title becomes `"Service - Manage Stock Items - LLD"`).

### Labels
Apply labels: `lld`, `auto-generated`, `dotnet`, `<jira_project_key_lowercase>`

### Page Content Structure

Follow `.claude/templates/lld-confluence-template.md` section by section, in order.

For all Confluence Storage Format HTML — info panels, warning panels, code blocks, status badges, tables, heading levels, and the Markdown-to-HTML conversion mapping — use **`.claude/skills/confluence-operations/SKILL.md`** Part 2. Do not write Confluence macro HTML from memory.

**1. Auto-generated notice panel**
```html
<ac:structured-macro ac:name="info">
  <ac:parameter ac:name="title">Auto-Generated by Technical Lead Agent</ac:parameter>
  <ac:rich-text-body>
    <p>
      This LLD was generated on <strong>{date}</strong> from 
      Epic <a href="{jira_url}">{epic_id}: {epic_title}</a>.
      <br/>
      Source: <a href="{hld_url}">HLD</a>
      {frd_link_if_available}
    </p>
  </ac:rich-text-body>
</ac:structured-macro>
```

**2. Table of Contents macro**
```html
<ac:structured-macro ac:name="toc">
  <ac:parameter ac:name="maxLevel">2</ac:parameter>
</ac:structured-macro>
```

**3. Each LLD section as `<h1>` / `<h2>` with content**

Convert each Markdown section:

| Markdown | Confluence HTML |
|----------|----------------|
| `## heading` | `<h1>heading</h1>` |
| `### subheading` | `<h2>subheading</h2>` |
| Mermaid code blocks | Code macro with `mermaid` language |
| YAML code blocks | Code macro with `yaml` language |
| Tables | Native HTML tables |
| Bold text | `<strong>` |
| `[NEW]` tag | `<ac:structured-macro ac:name="status"><ac:parameter ac:name="colour">Green</ac:parameter><ac:parameter ac:name="title">NEW</ac:parameter></ac:structured-macro>` |
| `[MODIFIED]` tag | `<ac:structured-macro ac:name="status"><ac:parameter ac:name="colour">Yellow</ac:parameter><ac:parameter ac:name="title">MODIFIED</ac:parameter></ac:structured-macro>` |

**Mermaid code block:**
```html
<ac:structured-macro ac:name="code">
  <ac:parameter ac:name="language">mermaid</ac:parameter>
  <ac:plain-text-body><![CDATA[
    {mermaid_content}
  ]]></ac:plain-text-body>
</ac:structured-macro>
```

**YAML code block:**
```html
<ac:structured-macro ac:name="code">
  <ac:parameter ac:name="language">yaml</ac:parameter>
  <ac:parameter ac:name="theme">Midnight</ac:parameter>
  <ac:plain-text-body><![CDATA[
    {yaml_content}
  ]]></ac:plain-text-body>
</ac:structured-macro>
```

## Step 3 — Create or Update the Page

**Create (new page):**
```
Tool: createConfluencePage
Input: {
  spaceKey: "<SPACE_KEY from config>",
  parentId: "<hld_page_id>",
  title: "<hld_core_name> - LLD",
  body: "<full_confluence_html>",
  contentFormat: "html"
}
```

**Update (existing page — revision):**
```
Tool: updateConfluencePage
Input: {
  pageId: "<existing_lld_page_id>",
  title: "<hld_core_name> - LLD",
  body: "<full_confluence_html>",
  contentFormat: "html",
  version: <current_version + 1>
}
```

---

## Step 4 — Update Jira Epic

After successful Confluence publish:

**Add remote link to epic:**
```
Tool: (use Jira API via Atlassian MCP)
POST /rest/api/3/issue/<epic_id>/remotelink
Body: {
  "object": {
    "url": "<new_confluence_lld_url>",
    "title": "<lld_title>",
    "icon": {
      "url16x16": "https://confluence.atlassian.com/favicon.ico",
      "title": "Confluence"
    }
  }
}
```

Do **not** add a comment to the Jira epic.

## Notify Skill

At the end of this agent's execution, invoke the Notify Skill (`.claude/skills/notify-skill/SKILL.md`):

Follow `.claude/skills/notify-skill/SKILL.md` exactly — two steps every time:

**Step 1 — Desktop toast:**
```bash
bash .claude/scripts/notify.sh "Confluence Publisher Agent" "<Status>" "<Summary>"
```

**Step 2 — Push notification (always runs after Step 1, regardless of toast outcome):**
```
PushNotification
  message: "Confluence Publisher Agent — <Status>: <Summary>"
  status: "proactive"
```

Keep the push message under 200 characters. If either step fails, log and continue — notifications never block the pipeline.

**Summary examples for this agent:**

| Status | Example Summary |
|--------|----------------|
| Completed | LLD published to Confluence as child of HLD. Jira epic {epic_id} updated with link. |
| Blocked | Confluence publish failed — {error}. LLD saved locally at output/{epic_id}/<hld_core_name> - LLD.md. |

Follow the summary authoring rules in the skill file:
- 1–2 sentences, past tense, plain text, no markdown
- `Completed`: state the key output
- `Blocked`: state the blocker and what is needed
- `Failed`: state what failed in plain terms

Failure of the notify script does **not** block the workflow — log and continue.
